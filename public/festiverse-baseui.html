Festiverse Design System

This is the original Festiverse reference rebuilt so every interactive pattern is a real shadcn/ui-style component running on @base-ui-components/react instead of raw Tailwind soup — Base UI marks a real primitive component below, Custom marks a Festiverse-specific pattern with no shadcn equivalent (documented instead of faked). Colors, radius, shadows and fonts all still come from the same CSS-variable tokens as festiverse-theme.css — nothing was re-themed. No build step: React 19 + Base UI load as native ES modules from esm.sh, JSX is stripped in-browser by Babel Standalone.

Typography

Inter (body/UI) + Lexend (display, h1–h4) + JetBrains Mono (code) — same three-font stack as the source app, wired via --font-sans / --font-display / --font-mono.

Foundations

Layout & Breakpoints

Mobile-first, single-column PWA. The shell caps content width even on desktop rather than reflowing into a multi-column layout — a deliberate "phone-shaped" constraint, unrelated to component library choice.

  • max-w-3xlMain app content
  • max-w-mdCentered dialogs
  • max-w-smLogin card
Core Components

Button Base UI

One cva-driven <Button variant size> replaces every ad-hoc button in the source. Standard shadcn variants (default / secondary / outline / ghost / destructive / link) plus two Festiverse-specific ones (cta = pill + glow, gradientPurple/gradientOrange = role-action tiles).

Core Components

Badge Base UI

Category tags, role badges, and status/price tags all render through one <Badge variant> component; per-category color is passed as a className override on top of the base variant, matching the source's CATEGORY_TAG_COLORS map.

Core Components

Field / Input Base UI

Built on Base UI's Field primitive (label/control/description/error wired together via ARIA automatically), replacing the source's literal const INPUT = "..." string constant.

Core Components

Card Base UI

Card / CardHeader / CardTitle / CardDescription / CardContent / CardFooter — the same compound-component shape as shadcn's Radix Card, since Card itself has no interactive primitive to swap.

Navigation

App Shell (Top Bar) Custom

The sticky, blurred top bar you see on this very page is the real pattern — .glass utility (85% bg + 12px blur). There's no shadcn "AppBar" primitive; this stays hand-built Tailwind, now reading from tokens instead of hardcoded white/black.

Bottom Navigation Custom

Fixed 4-item icon+label bar. Active state swaps the Solar icon from -linear to -bold rather than just recoloring — a distinctive Festiverse touch worth keeping exactly as-is. No shadcn primitive covers a mobile tab bar, so this stays custom.

Click a tab — icon swaps linear↔bold, label swaps medium↔bold.

Navigation

Tabs & ToggleGroup Base UI

The source has three visually distinct tab-like patterns. Two map cleanly onto Tabs (segmented pill + underline), the filter-chip row maps onto a single-select ToggleGroup since chips aren't really "views," they're multi-criteria filters.

Day Switcher — <Tabs> with a sliding <Tabs.Indicator>

Filter Chip Row — <ToggleGroup> of <Toggle>, single-select

Underline Tab Bar — <Tabs>, admin dashboard style

Menu (Dropdown) Base UI

Menu.Root / Trigger / Portal / Positioner / Popup / Item — the theme switcher from the top bar of this very page. Base UI uses an explicit Positioner between Portal and Popup where Radix folds positioning into Content.

The live theme toggle is also in the top bar — same component.

Content Patterns

Popover Base UI

Popover.Root / Trigger / Portal / Positioner / Popup — the floating event card. Base UI ships its own open/close transition data-attributes (data-starting-style / data-ending-style) so Framer Motion isn't required for the enter/exit animation the source used.

Content Patterns

Accordion Base UI

Accordion.Root / Item / Header / Trigger / Panel, single-open. Panel height animation uses Base UI's built-in CSS custom property for measured height rather than a hardcoded grid-rows hack.

Overlays & Feedback

Dialog & Sheet Base UI

Both the centered modal and the bottom sheet are the same Dialog primitive — a Sheet is just Dialog with a side="bottom" style variant, exactly how shadcn's own Sheet is built on top of Dialog.

Overlays & Feedback

Toast Base UI

Toast.Provider / Viewport / Root + useToastManager(). Base UI shipped a native Toast component in July 2026 — double-check the exact API against base-ui.com/react/components/toast before shipping, this reference was written from the best available docs at build time.

Overlays & Feedback

Skeleton / Empty States Base UI

A one-line <Skeleton> (styled div, no primitive needed) plus the source's consistent empty-state pattern: 48px muted Solar icon over one line of centered muted text.

Full Pages

Auth / Error Pages Custom

Full-bleed gradient "threshold" screens — reserved for entering/lost moments, breaking from the neutral background used everywhere else. Not a component pattern, kept as page-level custom markup.
